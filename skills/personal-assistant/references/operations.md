# Source records

Use [indexed storage](storage.md) for configured schema2 intake, exact CAS contracts, bounded recovery and migration. The normal interface is one `scripts/intake_tools.py --config <private-host-config>` batch on stdin. Ordinary `calls` only store/recover source. The explicit bounded [return finish](returns.md) and [task trigger finish](task-triggers.md) branches can commit one timer through the existing durable journal; none sends. Do not read/print whole source JSON, SQL tables, preferences or raw memory output. Ordinary `status:ok` acknowledges the entire committed source batch. Cross-store `status:partial` explicitly reports source/reservation committed with the timer/ack held; preserve its exact identity for deterministic reconciliation rather than claim no mutation or a scheduled return.

Initialization is a separate explicit fresh-user operator operation, requiring Python3.9+, SQLite FTS5 and IANA timezone data. `new_workspace.py` creates a new empty private directory with schema2 source and disabled activation settings; it refuses an existing workspace. `source_store.py init` creates a new path only, never implicitly upgrades or reuses a store. Paths and namespace are private host bindings. Existing users require the reviewed preservation/migration/cutover procedure under a fresh sole-writer pause and helper stop.

For a schema2 event, store exact ID, title, active/cancelled status, local_time, timezone, start_utc, source, source_wire_id, preparation_minutes and buffer_minutes. Use the reviewed local-time/DST resolver to calculate UTC start; if wall time is ambiguous ask for fold, and reject a nonexistent time. The source checks local/UTC agreement; UTC disambiguates fold. Preparation subtracts elapsed UTC effort/buffer. Unknown original fields remain privately preserved. New tasks explicitly use schema2 task semantics and prerequisite IDs; do not infer semantics of a legacy task object.

For legacy JSON, retain its existing sole writer and read-only event recovery until managed cutover. `legacy_source.read_context(path, ref, namespace, max_nodes=None)` is compatible only with verified schema1 events. It reads the complete stable private document without a local byte or collection-count cutoff and emits only the complete selected privacy-approved projection; unknown task semantics, statuses, estimates, duplicate IDs, local/UTC disagreement, changing/symlink/nonprivate state hold. The fingerprint covers complete selected originals and stable namespace. `metadata_check` returns readiness booleans only. Preferences remain separate. Atomic JSON replacement without revision CAS is a legacy constraint, never a reason to add another writer.

Exactly one backend is configured: legacy `source_json` plus canonical source_namespace, old already qualified SQLite schema1 through the read-only `source_store_v1.py` compatibility adapter, or indexed `source_db` with `source_schema:2` and preserved source_namespace. Ordinary intake requires schema2. Runtime `inspect` chooses its configured backend and returns the source context. No backend fallback can silently reinterpret records or reset a draft fingerprint.

Archive requires explicit terminal status and actual external reference clearance by the operator, graph/mapping checks, and remains reversible; it is excluded from normal intake. No retention threshold or destructive deletion is enabled. Restore leaves terminal statuses intact and creates no timer. Existing schedule/dedup/lineage and uncertain evidence must remain resolvable.

Operator exports and consistent backups are recovery artifacts kept private. `export_legacy` preserves original records and opaque partitions; full `export_state`/SQLite backup additionally preserves internal mappings, receipts and semantic pointers. Keep the separate schedule journal and current ledger. After new writes, fixed fallback retains current indexed state and disables contextual sends; never restore a stale source/ledger or old writer.
