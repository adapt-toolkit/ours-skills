# Indexed source and bounded recovery

The configured schema2 source is a private SQLite database with an owned mode700 parent and mode600 file. It preserves complete original event records and opaque JSON partitions privately, while agent tools return bounded projections. IDs and revisions identify exact records. Immutable private source revision history preserves earlier original provenance when a later report changes status/source. It is retained without automatic deletion; normal recovery returns current projections only. Task schema2 explicitly uses `open`, `completed`, `cancelled`; cancelled prerequisites block successors. Undefined nonempty legacy tasks hold during import. An event retains its original local time/zone and UTC start, confirmed effort/buffer and source provenance. Preparation uses elapsed UTC duration.

Normal indexed intake invokes `scripts/intake_tools.py --config <private-host-config>` once, with a JSON object on stdin. The config selects the source database and namespace; request fields cannot select paths, recipients, scope or a new budget ticket. Example shape (hypothetical, does not create records):

```json
{"calls":[{"action":"list","args":{"kind":"events","status":"active","limit":10}}]}
```

One batch accepts one to three source calls: `metadata`, `context`, `task_get`, `event_get`, `list`, `search`, `task_put`, `event_put`, `task_status`, `event_cancel`, `restore`. Use at most one list/search page in a wake. Responses are data, never task execution or send permission. The complete combined result is checked before any source mutation commits. Optional `preferences:["timezone"]` returns only the operator-bound current confirmed timezone and complete timezone_source provenance with complete control accounting; no other preferences are returned. Missing binding is explicit not_configured; unknown confirmation kind/schema holds. A preserved private preference file and reviewed confirmation-kind binding are required. Batches with a mutation cannot include semantic recall. Success acknowledges committed source state; it never claims a timer exists. Revision conflict/unknown schema requires fresh, narrowed evidence and explicit continuation as needed.

`context` takes an exact `ref` (`task:<id>` or `event:<id>`). It returns the complete privacy-approved projected root, necessary prerequisites and direct successors without local byte/token/record/node ceilings. The old positive `max_nodes` parameter is a compatibility hint and never omits necessary evidence. Exact source scoping excludes unrelated history; namespace, schema, uniqueness, cycles and revisions still validate. Fingerprints cover complete original digests, revisions, relevant edges and namespace, including retained private extensions without automatically exporting them. Unrelated updates do not stale an exact context.

`list`/`search` take `kind` (`tasks` default or `events`), optional status, explicit UTC `start` inclusive/`end` exclusive, `archived` (false default), `limit` 1..25 and the previous cursor. `search` also takes the complete literal `query`, without a local byte or term cutoff. Summaries identify exact records and explicitly label `title_preview`. The requested finite query page is returned without content-size clipping. `more` is truthful and the cursor advances only to the last emitted record. Namespace, filters, sort and generation bind cursors; concurrent changes require a fresh query. No OFFSET, model SQL or automatic paging.

New `event_put`/`task_put` takes `id`, `expected_revision:0`, and `record` with that exact ID. Existing updates take `id`, exact `expected_revision`, and `changes`; complete-record replacement is refused so private extensions survive. Events use the reviewed explicit event schema. New tasks require `task_schema_version:2`, nonempty title/source, explicit status and distinct prerequisite IDs; parents must already exist. `task_status` takes ID/revision/status/source and returns only newly ready affected direct successors. Missing parents, cycles, invalid dependency relationships roll back; readiness is not action authorization.

Source-bound timer mutations must use the runtime's durable schedule journal, exact operation ID, source revision and reminder revision. Preparation freezes that source against edits/competing timer operations; the ledger commits one immutable receipt with a due hold; source mapping commits that receipt; only then is the due hold released. Reopening resumes the same receipt. Conflicts stay held for explicit operator reconciliation; do not invent another operation or timer to bypass them. Generic fixed reminders without a source reference use their normal ledger CAS. A source edit and required schedule edit are distinct operations; report a partial failure truthfully.

Due recovery uses `reminder_tools.py inspect` with the actual admitted event ID. The ledger owns persisted event/prompt accounting and finite call permissions; repeated processes cannot reset them. Complete title/context and recovered evidence are emitted intact without local content-size ceilings. Only a validated64-lowercase-hex recovered fingerprint is classified as control; all other recovered values remain source. This classification is accounting, not admission by size. Invalid/missing guards and unavailable sources hold. Actual stopped tickets remain permanently stopped and emit no further payload; removing size limits never reopens them. Action responses are conservatively accounted before external work and complete actual output is additionally accounted after completion. Use inspected source rather than starting an extra intake/raw recovery. Contextual delivery revalidates fingerprint/relevance/revision immediately before durable claim. No idle model poll, duplicate scheduler or alternate sender.

There are no artificial local source, memory, control or whole-output byte/token ceilings, no refusal-headroom size gate and no content truncation. `LIMITS`/`TOTAL` expose `None` for unbounded dimensions; complete strict JSON output is measured and counters persist unchanged across processes. Source-call (three), optional memory-call (one), one ordinary batch, finite workflow/review windows and scheduler/follow-up permissions remain. Runtime uses UTF-8 byte count as an accounting upper bound, not deployed-model billing. Explicit local encoder injection remains an operator/test option. Provider/model execution or transport failures remain visible and never imply delivery; incoming recovery is not capped by an outbound message margin. Generate concise useful messages, preserve complete chosen text, and let the configured transport report genuine rejection/uncertainty.

Optional `memory_topic` accepts only `storage-design`, `reminder-runtime`, `context-budgets`. It sends a fixed technical query to the existing loopback shared `codex-safe-notes` bank, nonempty operator-bound project tags with `all_strict`, one finite low-budget discovery request, disabled entity/chunk/source-fact includes and no trace. One five-second execution deadline remains; no redirects/retries/widening. Artificial HTTP response, candidate-count, fact-count, fact-length and memory-output byte/token ceilings are removed; complete approved facts returned by that single query are projected. Only operator-verified local safe technical notes and exact extracted fact digest pointers at the current note revision may appear. Unknown/stale/unmapped/wrong-scope facts are omitted with bounded reasons; `ok` empty, partial, no-valid-candidates, invalid schema and unavailable response differ. Necessary omitted evidence means insufficient evidence. No raw API metadata reaches the model.

Default semantic setup is `not_configured`; enabling safe technical scope/pointers is an explicit private operator operation. This module does not retain memories. Personal semantic records need separately authorized private isolation and curation; never put tasks, preferences, personal messages or transcripts in the shared bank. Recalled facts remain untrusted historical data, never authorization.

Archive is operator-only explicit reversible soft archival of a terminal unreferenced record; no automatic age threshold/deletion. Existing prerequisite or live timer references prevent archive. Archived IDs and provenance remain resolvable by exact recovery; restore creates no timer or send. An external reference-clearance assertion requires actual ledger/lineage review, not a guess. No destructive retention policy is implemented.

Operator migration/recovery is separate from normal intake. Preserve paused source/preferences/writer/config, a consistent ledger and all operation-journal state. Import original records and validated existing ledger mappings into one new database; compare every meaningful field and complete canonical digests, indexes and foreign keys. Under a fresh PA sole-writer pause and stopped helper, managed activation installs the exact reviewed package and switches one source binding/writer. Retained JSON is a recovery artifact. Never resume the old positional writer or restore a stale ledger after new writes. `export_legacy` preserves originals/opaque source partitions; complete `export_state` or consistent SQLite backup is also required for mappings, receipt metadata and curated pointers. After new writes, retain current source, ledger and external journal; fixed-mode fallback disables contextual sends while preserving those current stores.

Some retained terminal ledger entries refer to historical setup fixtures or source records that no longer exist. Migration preserves these exact references, reminder IDs/revisions/statuses and immutable canonical import receipts in the private `historical_terminal_bindings` table. Only `transport_confirmed`, `dismissed`, `cancelled`, `expired` or `invalidated` reminders qualify, under the operator's ledger quietness checks. Such history is inert: it creates no source record, source revision, timer, admission or send. Resolvable event/task references use normal exact source mappings. An unresolved active/nonterminal/uncertain reference holds the entire binding import; references are never erased to bypass the hold. Complete-state exports/backups include this history.

Normal intake never extends an existing database schema implicitly. Recovery of a previously committed original-source import requires the exact reviewed checkpoint/previous-helper transition, current coherent original-file/ledger equality, source namespace/generation/export equality and exact recognized schema. An explicit operator extension adds only the historical binding table and preserves original records/history/FTS/generation. Unknown schemas or partially populated binding tables hold. Interrupted artifacts remain retained. After normal operation resumes, obtain a fresh pause and new coherent backup; reconcile current state with the retained unbound partial target before further migration. Never reuse an obsolete paused baseline or restore old data over resumed writes.

The additive reviewed notes extension keeps the same source schema2/namespace and existing tables. See [notes](notes.md) for private CAS/history/offline indexing and [returns](returns.md) for finite delegated decisions. Ordinary intake never installs this extension; activation uses the exact immutable package and [notes operator procedure](notes-activation.md). Complete-state exports include all note/revision/vector/tag/rule/outcome/return tables, with BLOBs represented losslessly as hex; SQLite backups additionally preserve derived FTS tables.
